**효용이 인정된 부분** (반증 시도 후 생존):
- 결과 기준 3축(영향·되돌림 비용·검증 가능성)은 크기 기준(LOC)보다 우월 — 작지만 위험한 변경(1줄 인증 수정)이 자동 T3에 걸림.
- T1 단축 흐름은 "지킬 수 없는 규칙 → 전면 사문화"를 막는 생존 장치 (15단계 풀 흐름 60% 사문화 실패 경험에 근거).
- 과소/과대 분류 비용의 비대칭을 "의심 시 상향 + 자동 T3 목록"으로 처리한 설계는 타당.

**기각·교정된 부분**:
- claude R1의 "판단 1회로 압축" 효용 주장 → **과장으로 교정**. 문서 §6.1/§6.5가 시점별 재평가를 요구하므로 정확한 기술은 "분류 1회 + 발동 판정 N회(분류를 입력값으로 재사용)".
- gemini의 "사용자가 raw 리뷰를 알 방법이 없다" → **과장으로 교정** (§6.7이 raw 경로 명시를 의무화). 단 요약자 편향(심판=선수) 위험 지적 자체는 유효 → 수정 패키지 6번으로 흡수.

## 잔여 이견·한계 (지우지 않고 보존)

1. **별도 요약 세션(심판-선수 분리)**: gemini가 제기 → claude가 "1인 환경 운영비 대비 과잉"으로 기각, gemini는 "§10 사후 점검의 엄격한 실행"을 전제로 수용. **기각 판단 자체가 [미검증]** — §10 점검에서 요약-raw 불일치가 반복 검출되면 재론한다.
2. **재브리핑 "초단축(1분 내외)" 형식**: gemini 단서로 채택됐으나 구체 형식은 미정 — 수정 반영 시 정의 필요.
3. **이 결론 자체의 한계**: 세 참여자 모두 LLM이라 실패 모드가 상관됨. 문서 라인 인용으로 정박했으나, "수정안이 실제로 사문화를 막는가"는 실행해봐야 아는 명제다. **walk-forward 체크**: 수정 반영 후 첫 5개 PR에서 Tier 기록 스키마가 실제로 채워지는지 §10 첫 월간 점검(소유자: 사용자)에서 확인할 것.
4. **운영 사고 기록**: gemini(0.45.2)가 R2를 board EOF가 아닌 자기 R1 뒤에 삽입하며 종료마커 2개를 유실시킴(본문 무결, 진행자 복구). 다음 토론에서 gemini는 single-writer 폴백 고려.

## 토론 경과 요약

- **R1**: claude "유지+보완 3개"(0.8) → codex가 내적 일관성 렌즈로 "판단 1회" 주장 반박 + T1 expectation 충돌 등 6개 결함 적발(수정, 0.78) → gemini가 현실성 렌즈로 검토 부하·Orchestrator 편향 제기 + codex의 소급 보강안 비판(수정, 0.85).
- **R2**: claude가 9건 오라클 검증 원장 작성 + 자기 주장 과장 정정 + Q2b 중재안 제시(0.85) → codex 중재안 찬성·원장 이의 없음(0.86) → gemini 중재안 찬성·교정 2건 수용·원장 이의 없음(0.88) → **수렴 종료**.
- 빠른 만장일치가 아니라 상호 반박(claude 주장 1건 기각, gemini 주장 2건 교정, codex 제안 1건 조건화)을 거친 수렴임을 명시한다.
