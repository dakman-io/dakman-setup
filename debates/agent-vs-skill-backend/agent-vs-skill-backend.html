핵심 결론

옵션 B — 에이전트 1개(backender) + 스킬 2개(spring·fastapi) + backender-checker(checker 쌍) 이 기본값.

축: 에이전트 = 역할(안정축, "누가") / 스킬 = 교체 가능한 지식(변하는축, "무엇으로") → 변하는 축(스택)을 교체 가능한 층(스킬)에 둔다.

결정룰 — 한 줄

지식(프레임워크) 차이 → B  /  역할 판단·권한·checker 기준이 반복적으로 갈리거나, 도구권한이 하드 보안경계거나, 한 세션이 多스택을 오가거나, N이 영구 2 고정 → A

01

설계 축 — 무엇을 어디에 두는가

안정축 · "누가"
에이전트 = 역할
잘 변하지 않는 책임/권한의 축. 한 곳에 고정한다.
→
변하는축 · "무엇으로"
스킬 = 교체 가능한 지식
프레임워크·스택처럼 갈아끼우는 축. 교체 가능한 층에 둔다.

변하는 축(스택)을 교체 가능한 층(스킬)에 두는 것 — 이것이 B를 기본값으로 만드는 한 문장 논리다.

02

왜 B인가

5 근거
근거 01 · 역할 단일 정본

역할 로직은 스택 무관 동일 → 1곳 작성, 드리프트 0

backend 역할 로직(요구 해석·변경범위·테스트/마이그레이션 판단·리뷰대응·보안·보고)은 스택과 무관하게 동일하다. 한 곳에만 쓰면 드리프트가 0. A는 역할 로직을 두 에이전트에 복제한다.

근거 02 · 컨벤션 정합

"에이전트=역할, 스킬=지식" 그대로

기존 설계 컨벤션을 변형 없이 따른다.

근거 03 · 확장성

스택 N개 = 에이전트 1 + 스킬 N

스택이 늘어도 에이전트 1개 + 스킬 N개(django·nestjs…)면 된다. A는 에이전트(+checker) N개로 불어난다.

근거 04 · 컨텍스트 효율

스택 스킬만 온디맨드 로드

그 프로젝트가 쓰는 스택 스킬만 필요 시 로드한다.

근거 05 · checker 단순

backender-checker 1개로 공통 품질기준 유지

checker 1개가 공통 품질기준을 유지한다(필요 시 스택 검증 스킬 호출).

03

A가 맞는 예외 — 반대 옵션 조건

아래 조건들이 성립하면 옵션 A(스택별 별도 에이전트)가 정당화된다. 프레임워크 지식이 아니라 역할/거버넌스 차이가 핵심이다.

  • A·1

    스택별로 역할 판단·운영 책임·품질 기준·실패 모드·checker가 실제로 다를 때 (프레임워크 지식이 아니라 역할/거버넌스 차이).

  • A·2

    도구·배포·시크릿 권한이 하드 보안경계라 에이전트 수준 격리가 필요할 때.

  • A·3

    한 세션이 여러 스택을 오가거나(예: monorepo), 스택→스킬 바인딩이 재량적일 때.

  • A·4

    N이 영구 2 고정이고 공통 워크플로우 공유 필요가 없을 때.

04

B의 전제 = 결정론적 바인딩

행동 항목
⚠️

희망이 아니라 강제해야 한다

B의 안전성(스택 관용구 혼입 0)은 "backender가 어느 스킬을 쓸지가 결정론적으로 고정"된다는 데 의존한다. 이것은 강제되어야 한다:

  • project-init이 각 repo CLAUDE.md에 stack → skill을 못박는다 (예: "이 repo는 Spring → spring 스킬만").

  • 스킬 frontmatter에 hard stack-guard ("타 스택 관용구 금지").

이 강제가 있으면 신뢰도 上, 없으면 中으로 하향 (혼입 리스크가 실재화 → A 경쟁력 상승).

검증 원장

주장 · 판정 · 근거

⚠️ 추론 #6 실행검증 안 함
@Transactional(Spring thread-bound) vs FastAPI(async event-loop, session-per-task) 기본값 뒤집힘
근거 · 판정
프레임워크 설계상 알려진 사실이나 본 토론서 오라클 실행검증 안 함. 판정: 역할 판단 분기는 맞으나 repo 컨텍스트 고정 + 스킬 stack-guard로 통제 → A로 밀지 않고 B 위 설계조건으로 강등(claude 자기 prosecutor 강등, 3자 합의).
⚠️ 잔여 이견 #7 미해소
신뢰도 上 vs 中
근거
범위 해석 차 — in-scope(별 repo 2개, working-dir가 스택 고정) = 上(claude) / 혼입 리스크 hedge = 中(codex·agy). monorepo·교차스택 세션이면 中~A 재평가.
06

지워지지 않은 것들

잔여 이견 · 메타 주의
⚖️

잔여 이견

지우지 않음
  • 신뢰도: claude 上(in-scope) ↔ codex·agy 中. 핵심 변수 = "stack→skill 바인딩이 결정론이냐 재량이냐". 결정론 강제(위 행동항목) 시 上으로 수렴 가능.
  • 따라서 결론은 "B + 결정론적 바인딩 강제"가 한 묶음. 바인딩이 보장 안 되면 신뢰도 하향·A 재검토.
