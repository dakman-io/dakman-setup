회원가입 · 인증 스키마 D2 ERD

렌더: D2 → d2 --layout elk --direction right → 오프라인 SVG 인라인 (외부 CDN 0개, 폰트 임베드). 출처는 erd-signup.d2 한 파일 = 단일 진실의 출처. (DBML 대안 프로토타입)

Core — 정체성·권한. 네가 설계·지킴. 정규화, 바꾸기 어려움 Edge — 세션·토큰·로그. append-only/휘발성. AI 자유, 버려도 됨

이 스키마가 박고 있는 설계 결정

① 정체성 ≠ 인증수단

users는 "누구인가"만. "어떻게 로그인하나"는 auth_identities로 분리. 한 유저가 비밀번호+구글+애플 동시 보유, 소셜전용(비번 없는) 유저도 자연스러움.

② status = 상태기계

pending → active → suspended → deleted. 기능마다 status를 자유롭게 찌르지 말고 허용된 전이만. 가입 = 엔티티 생애주기 시작 = 불변식의 핵심.

③ core vs edge

Core(users·identities·roles)는 정규화·신중. Edge(sessions·tokens·events)는 휘발성/append-only라 AI 자유. 같은 엄격함을 둘에 다 쓰지 않는 게 속도의 비결.

④ 단일 진실의 출처

"이메일 검증됨"의 진실은 users.email_verified_at 한 곳. auth_tokens는 *절차*일 뿐 상태가 아님. 검증 상태가 두 곳에 살면 드리프트 = 사고.

⑤ 제약 = AI가 못 깨는 가드레일

email UNIQUE, (provider, provider_uid) UNIQUE, 전 FK에 ON DELETE CASCADE(events만 SET NULL). 기능 코드가 틀려도 DB가 막음.

⑥ soft delete = 가역성

탈퇴는 행 삭제가 아니라 status=deleted + deleted_at. 실수·복구·법적 보관 대응. 비가역(진짜 DELETE)을 가역으로 바꾸는 1원칙의 실제 적용.

⑦ 토큰은 해시만, 원문 금지

sessions.refresh_token_hash·auth_tokens.token_hash — 평문 저장 X. DB 유출돼도 토큰 재사용 불가. 글로벌 B2C 기본값.

⑧ auth_events = 감사 로그

append-only edge 테이블. 가입·로그인·실패 기록 → 이상탐지·디버깅·컴플라이언스. core를 더럽히지 않고 관측성 확보.

# 회원가입·인증 스키마 — D2 (DBML 대안 프로토타입)
# 원리: 정체성≠인증수단 / core·edge 분리 / 상태기계 / 단일 진실의 출처
# 렌더: d2 --layout elk --direction right erd-signup.d2 erd-signup-d2.svg
# DBML 대비 강점 = 컨테이너로 core/edge 그룹 유지 + ELK 레이아웃 엔진으로 가로 배치 제어

direction: right

# ===================== CORE =====================
core: core {
  style.fill: "#eef2ff"
  style.stroke: "#6ea8fe"

  users: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    email: citext {constraint: unique}
    email_verified_at: timestamptz
    status: user_status
    display_name: text
    created_at: timestamptz
    updated_at: timestamptz
    deleted_at: timestamptz
  }
  user_profiles: {
    shape: sql_table
    user_id: uuid {constraint: primary_key}
    avatar_url: text
    bio: text
    locale: text
    timezone: text
    preferences: jsonb
    updated_at: timestamptz
  }
  auth_identities: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    user_id: uuid
    provider: auth_provider
    provider_uid: text
    password_hash: text
    last_used_at: timestamptz
    created_at: timestamptz
  }
  roles: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    name: text {constraint: unique}
    description: text
  }
  user_roles: {
    shape: sql_table
    user_id: uuid {constraint: primary_key}
    role_id: uuid {constraint: primary_key}
    granted_at: timestamptz
  }
}

# ===================== EDGE =====================
edge: edge {
  style.fill: "#2d2417"
  style.stroke: "#f0a868"

  sessions: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    user_id: uuid
    refresh_token_hash: text {constraint: unique}
    user_agent: text
    ip_address: inet
    expires_at: timestamptz
    revoked_at: timestamptz
    created_at: timestamptz
  }
  auth_tokens: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    user_id: uuid
    purpose: token_purpose
    token_hash: text {constraint: unique}
    expires_at: timestamptz
    consumed_at: timestamptz
    created_at: timestamptz
  }
  auth_events: {
    shape: sql_table
    id: uuid {constraint: primary_key}
    user_id: uuid
    event_type: auth_event_type
    ip_address: inet
    user_agent: text
    metadata: jsonb
    created_at: timestamptz
  }
}

# ===================== ENUMS =====================
enums: enums {
  style.fill: "#161a24"
  style.stroke: "#9aa3b2"

  user_status: {
    shape: sql_table
    pending
    active
    suspended
    deleted
  }
  auth_provider: {
    shape: sql_table
    password
    google
    apple
    kakao
  }
  token_purpose: {
    shape: sql_table
    email_verify
    password_reset
    magic_link
  }
  auth_event_type: {
    shape: sql_table
    signup
    login
    login_failed
    logout
    pw_reset
  }
}

# ===================== RELATIONSHIPS =====================
core.users.id <-> core.user_profiles.user_id: 1:1 {
  source-arrowhead: 1
  target-arrowhead: 1
}
core.auth_identities.user_id -> core.users.id: N:1
core.user_roles.user_id -> core.users.id
core.user_roles.role_id -> core.roles.id

edge.auth_tokens.user_id -> core.users.id
edge.auth_events.user_id -> core.users.id
